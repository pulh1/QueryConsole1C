# Пересмотр семантического анализа функций после пользовательского ревью

Статус: согласовано пользователем командой «Реализуй», 29.10.2026.
Реализация выполнена; результаты и ограничения проверок приведены в
[матрице покрытия](../matrices/2026-10-27-query-function-coverage.md).

## Цель и основания

Устранить разреженные по смыслу массивы ограничений типов и временную подмену
текущего запроса, оператора и роли в общем контексте. Проверять вложенность
функций в существующем обходе, сохранив поддержку 48 общих функций, генерацию
правильного имени НЕДЕЛЯ и ранее исправленные дефекты конструктора/вложенных
запросов.

Документ заменяет пункты 4 и 7 плана
[27.10](../plans/2026-10-27-query-functions-review-fixes.md) и соответствующие
части прежней [спецификации](2026-10-27-generic-query-function-calls-design.md).
Остальные договорённости сохраняются.

## Рассмотренные подходы

1. Создавать дочерний контекст на каждый запрос, оператор и выражение.
   Это убирает откат, но сохраняет хранение текущего положения в большом
   контексте и требует определить копирование всех его mutable-коллекций.
2. Передавать отдельные правила применения функций, вычисленные там, где
   запрос и оператор уже известны. Рекомендуется: окружение разрешения полей
   остаётся прежним, временное положение в него не записывается.
3. Проверять функции отдельным проходом по готовой модели.
   Добавляет второй обход и разносит семантические проверки; не рекомендуется.

Согласован и реализован вариант 2 вместе со стеком вызовов.

## Ограничения типов

Поле описания называется `ОграниченияТиповАргументов`, тип — Соответствие.
Ключ — целый номер аргумента с 1. Значение — непустой массив строк с допустимыми
типами. Нет ключа — `Получить(НомерАргумента)` возвращает Неопределено,
ограничение отсутствует.

Не хранить записи с пустым массивом или значением Неопределено. Для текущего
закрытого реестра корректность всех описаний проверяют контрактные тесты;
не вводить отдельный универсальный валидатор схемы на каждом вызове функции.

Строка `"Неопределено"` внутри массива остаётся разрешённым типом.
`"Ссылка"` остаётся специальной альтернативой, проверяемой существующим кодом.
Фактические типы аргументов остаются массивом с индексами с 0.
Допустимые количества аргументов остаются самостоятельным массивом чисел.

Оба потребителя используют `Получить(Индекс + 1)`:
проверка фактического типа и вывод ограничения непосредственного параметра.
Отсутствие записи должно поддерживаться до вызова `.Количество()`.
Сохраняются правила NULL, составных/произвольных типов и вывода результата.

ДАТАВРЕМЯ хранит числовые ограничения позиций 1–6, но принимает 3 или 6 аргументов.
ОКР хранит позиции 1–2, но принимает 1 или 2. ЕСТЬNULL и другие функции без
ограничения типов имеют пустое соответствие независимо от своей арности.

## Явные правила применения функций

Базовый контекст содержит окружение разрешения полей/источников/ВТ.
Поля `ЗапросВыбора`, `ОператорЗапроса`, `РольВыражения` из него и из
контекста обработки запроса удаляются. Ссылки на текущие объекты не сохраняются
в посетителе как замена этих полей.

В ОбработкаМоделиЗапроса реализованы фабрики:

- `НовыеУсловияПримененияФункций()` — режим отдельного выражения.
- `УсловияПримененияФункцийОператора(Оператор)` — проверка внутри оператора.
- `УсловияПримененияФункцийВыбираемогоПоля(Запрос, Оператор, Выражение)`
  — проверка конкретного выбираемого поля.

Фабрики с оператором требуют действительный оператор, без Неопределено.
Структура всегда имеет три обязательных свойства:

| Свойство | Тип и смысл |
| --- | --- |
| ПроверятьКонтекстЗапроса | Булево; Ложь только при самостоятельном анализе выражения |
| РазрешенАвтоНомерЗаписи | Булево; окончательная допустимость именно этого выражения |
| ВыраженияГруппировки | Массив элементов группировки оператора, доступный только для чтения |

В отдельном выражении значения — Ложь, Ложь, пустой массив. Внутри оператора —
Истина, Ложь, его элементы группировки. Для выбираемого поля дополнительно
вычисляется допустимость АВТОНОМЕРЗАПИСИ.

Правила после создания не изменяются и не кешируются в реестре.
Никаких проверок наличия обязательных свойств через Свойство.
Отсутствующий обязательный оператор — ошибка вызывающего кода,
а не повод пропустить проверку.

Правила передаются обязательным аргументом. Самостоятельный вывод типа
явно получает НовыеУсловияПримененияФункций(); пропуск аргумента не должен
молча отключать проверку запроса. Методы, уже получающие Запрос/Оператор,
сами вычисляют правила и не принимают дублирующий набор от вызывающего кода.
Остальные helpers получают правила обязательным параметром.

Посетитель создаётся для одного выражения через manager-фабрику
`СоздатьПосетитель(Контекст, РассчитываемыеСвойства,
УсловияПримененияФункций)`. Все три аргумента обязательны. Фабрика передаёт данные
существующим методам установки контекста/рассчитываемых свойств. При создании
инициализируются пустые стеки типов и вызовов. Отдельный метод начала обхода
не вводится. Повторное использование экземпляра после успеха или исключения
не входит в контракт; следующий анализ создаёт нового посетителя.
Правила не могут быть Неопределено.

`ОбработатьВыражение(Выражение, Контекст, РассчитываемыеСвойства,
УсловияПримененияФункций)` всегда создаёт посетителя сам. Параметр готового
посетителя удаляется: активных callers с ним не найдено. Единственный источник
входных данных — аргументы этой процедуры и её вызов manager-фабрики.
Известный прямой тест посетителя получает рассчитанные свойства через новую
сигнатуру фабрики. УстановитьКореньВыражения удаляется после миграции callers.
УстановитьРассчитываемыеСвойства остаётся частью внутренней инициализации
в manager-фабрике. УстановитьКонтекст принимает контекст и правила как два
обязательных аргумента. Сигнатуры callbacks обходчика сохраняются.

Все текущие самостоятельные callers мигрируют явно: два helper в
МодельЗапросаУтилиты, пробное определение типа в форме конструктора,
ТипВыражения в посетителе СКД и тесты. Это точечная передача правил;
callback-контракт и поведение этих потребителей не меняются.

Из ОбработатьЗапрос, ОбработатьОператор и ОбработатьЭлементыПорядка удаляются
блоки сохранения/подмены/восстановления трёх полей и обслуживающие их
Попытка/Исключение. ОбработатьВыражениеВРазделеЗапроса удаляется целиком.
Другие обработчики исключений, выполняющие предметные действия, этим решением
не затрагиваются. Откат модели после ошибки новым контрактом не обещается.

Для сортировки объединения ссылки на колонки обрабатываются как раньше;
прочие выражения отклоняются до семантического обхода. Для единственного
оператора правила берутся из него. При анализе итогов/индексов сохраняется
существующая привязка к первому оператору там, где текущие методы используют
его для поиска полей; это задаётся явно, не через пустой текущий оператор.

Параметры виртуальных таблиц, отборы, соединения, группировка, сортировка,
итоги и индексы получают правила с запрещённым АвтоНомером.
Фиктивная роль "Выборка" для отбора СКД не используется.

## АВТОНОМЕРЗАПИСИ

Справка установленной 8.3.24.1758, `shquery_ru.hbk`, тема RECORDAUTONUMBER,
и [официальное описание 1С](https://downloads.v8.1c.ru/content/Platform/8_3_13_1644/1cv8upd_8_3_13_1644.htm)
дают четыре условия:

1. Запрос создаёт ВТ через ПОМЕСТИТЬ.
2. У этого запроса нет ОБЪЕДИНИТЬ на верхнем уровне.
3. Функция находится в списке выборки.
4. Она самостоятельное поле, а не часть другого выражения.

В фабрике правил выбираемого поля проверяются запрос создания ВТ,
единственность оператора и то, что переданный корневой узел —
ВызовФункции с каноническим именем АВТОНОМЕРЗАПИСИ.
Сигнатура без аргументов проверяется обычным контролем арности.

Посетитель при встрече АвтоНомера проверяет уже рассчитанное разрешение.
Ни хранение корня, ни счётчик глубины всех узлов не нужны.
Обрамление вызова дополнительным узлом выражения сохраняет нынешний запрет;
отдельного расширения допустимости скобочных форм этот рефакторинг не вводит.

Группировка и агрегаты в других полях допускаются.
Объединение во вложенном источнике не равнозначно объединению верхнего
запроса: при создании внешней ВТ оно само по себе не запрещает АвтоНомер.
Вложенные запросы проверяются со своими правилами; разрешение внешнего поля
в них не передаётся.

СГРУППИРОВАНОПО проверяет ключи переданного оператора.
Решение об отключении проверки при пустой группировке заменено
[уточнением от 04.11](2026-11-04-groupedby-semantics-design.md) после
отдельного исполнения на выбранной пользователем платформе 8.3.27:
независимый от записей аргумент разрешён, зависимый должен совпадать с ключом.

## Стек вызовов и ПРЕДСТАВЛЕНИЕ

На входе в функцию проверяются имя/арность, затем добавляется кадр вызова.
При выходе кадр снимается. Стек контекста вызовов отделён от стека типов.

При входе в ПРЕДСТАВЛЕНИЕ известно, есть ли среди активных внешних вызовов
функция, которой нельзя передавать его результат.
ПРЕДСТАВЛЕНИЕ(ПРЕДСТАВЛЕНИЕ(...)) сохраняется разрешённым;
СТРОКА(ПРЕДСТАВЛЕНИЕ(...)) и СТРОКА(ПРЕДСТАВЛЕНИЕ(...)+...) запрещаются.
Проверка учитывает всю цепочку активных вызовов, а не только ближайшего родителя.

В стек включаются существующие callbacks функций с аргументами-выражениями:
общий вызов, КОЛИЧЕСТВО, периодные функции и приведение типа.
ТИП/ЗНАЧЕНИЕ не имеют аргументов-выражений и кадров не требуют.
Новые callbacks обходчика не добавляются.

Для вложенного запроса создаётся свой семантический посетитель и пустой стек.
Независимый запрос не наследует внешнюю функцию; выражения самого вложенного
запроса проходят собственную проверку.
При успешном завершении обхода стек вызовов пуст, в стеке типов один результат.
После ошибки экземпляр отбрасывается; следующий анализ создаёт новый
посетитель с собственными пустыми стеками, без cleanup через исключение.

СодержитВызовПредставления удаляется: повторных обходов дерева и отражательного
перебора полей структуры для этого запрета не остаётся.

## Имя метода и границы работ

ТипВызоваФункции переименовывается в
`ПроанализироватьВызовФункции(Выражение, ОписаниеФункции, ТипыАргументов)`.
Метод сохраняет проверку допустимых типов/специальных аргументов и вывод типа.
Проверка вложенности относится к посетителю и в эту утилиту больше не входит.

Меняются BSL-модули реестра, семантической утилиты, посетителя, обработки
модели и конструктора, тесты и актуальные документы.
При необходимости точечной передачи правил через helper меняется
МодельЗапросаУтилиты. Также точечно передаются обязательные standalone-правила
в форме конструктора и ОбработчикРазыменованийДляСКДПосетитель.
Из метаданных меняются только имена двух модулей реестра и ссылки на них.
Грамматика, AST, generated artifacts, callback-контракты visitors
и ПоставщикИсполняемыхПредставлений не меняются.

## Имена модулей и коммиты

По прямому указанию пользователя новые общие модули этого изменения именуются
без префикса КОНС_:

- КОНС_РеестрФункцийЯзыкаЗапросов → РеестрФункцийЯзыкаЗапросов.
- КОНС_РеестрФункцийЯзыкаЗапросовПовтИсп → РеестрФункцийЯзыкаЗапросовПовтИсп.

Переименование выполняется через EDT-MCP с preview ссылок и последующим
применением. Сохраняются UUID и свойства модулей, включая DuringSession
у обёртки. Прежние имена-алиасы и новые модули-дубликаты не создаются.
Префиксы существующих тестовых модулей YAxUnit не затрагиваются.

До реализации текущее состояние фиксируется отдельным baseline-коммитом.
Все изменения по этому согласованному плану оформляются одним итоговым
коммитом: без промежуточных коммитов этапов, merge и push.
