# PR: единые границы metadata provider для семантики и UI

PR: https://github.com/pulh1/QueryConsole1C/pull/79

Ветка: `feature/metadata-provider` → `master`

Состояние: ready for review.

## Практический результат

- Семантика разрешает именованные таблицы и поля через единый реестр и
  точечные операции поставщиков.
- Стандартная схема создаётся один раз на корневой разбор; её каталог и поля
  раскрываются лениво.
- Временные таблицы, таблицы значений и вложенные запросы остаются локальными
  источниками модели и не получают отдельный поставщик.
- UI получает provider-owned корни и дочерние узлы через реестр и не знает
  конкретные provider objects или формат маршрута каталога.
- Raw `ДанныеПоставщика` читается только одним server-side адаптером
  исполняемых представлений; в UI и построителе модели прямых чтений нет.
- Производные контексты сохраняют явно заданное отсутствие реестра и не
  подменяют его штатным поставщиком.

## Оставшиеся ограничения

- Два headless UI-теста требуют реального `ДанныеФормыДерево` и покрыты
  Vanessa-сценариями.
- Один полный тест зависит от локализованного текста платформенного исключения.
- Один существующий consumer-тест пропущен из-за отдельного production defect
  `ОписаниеФильтра`/`ОписаниеВТФильтр`; этот PR его не меняет.
- Runtime MCP был подключён к другой ИБ, поэтому не использовался как
  доказательство этой ветки; symbolic CAPTURE не использовался.
