# Проверка объединённой реализации metadata provider

Дата проверки: 2026-09-02.

## Результат

Семантика и UI собраны в одной ветке `feature/metadata-provider`. Реестр
маршрутизирует точечный поиск таблиц и полей к одному экземпляру каждого
поставщика, а UI строит каталог через тот же реестр и раскрывает узлы лениво.
Временные таблицы и вложенные запросы остаются локальными источниками текущего
разбора и не превращены в глобальных поставщиков.

Функциональный acceptance пройден. Единственная ошибка полного YAxUnit-прогона
воспроизводится на чистом `master` и связана с языком текста платформенного
исключения. Три пропуска также не созданы этой веткой.

## Границы дизайна

- Реестр создаётся один раз для корневого разбора и передаётся в производные
  контексты; поставщики и их кэши живут столько же.
- Стандартный поставщик хранит статический список первых сегментов и не
  обходит `СхемаЗапроса.ДоступныеТаблицы` при инициализации.
- Семантика использует `НайтиТаблицу()` и `НайтиПоле()`; полное описание
  таблицы не строится в горячем точечном поиске.
- Полное нейтральное описание создаётся только там, где оно действительно
  нужно потребителю, в том числе для параметров исполняемого представления.
- Каталог UI получает корни и дочерние элементы через реестр. Изменений XML
  форм (`Form.form`) нет.
- `ИсточникДанныхВременнаяТаблица` разрешается по локальному описанию ВТ.
  `ИсточникДанныхВложенныйЗапрос` читает колонки вложенной модели. Остальные
  именованные таблицы маршрутизируются через реестр.
- Имена production-объектов не получили тестовый префикс `КОНС_`; он сохранён
  только в тестовом проекте YAxUnit согласно существующей схеме именования.

### EDT и статические инварианты

- основной EDT-проект переключён на commit ветки и импортирован;
- выполнено инкрементальное обновление тестовой ИБ;
- активных EDT debug launch не было;
- `.form` в diff отсутствуют;
- в семантическом hot path отсутствуют вызовы полного `ОписаниеТаблицы()` и
  `ТаблицаСуществует()`;
- `git diff --check` проверяется с учётом допустимого CRLF в сохранённых JSON
  benchmark artifacts.

EDT содержит существующий фон диагностик. Уменьшение или отсутствие новых
ошибок не трактуется как полностью чистый проект; блокирующих диагностик,
связанных с новым контрактом, не обнаружено. Общий snapshot EDT на момент
финальной проверки: 1291 marker, включая 36 `ERRORS`, 4 `BLOCKER`, 1
`CRITICAL`, 169 `MAJOR`, 1080 `MINOR` и 1 `TRIVIAL`; это фон всего проекта, а
не delta данной ветки. Для затронутых объектов использовалось сравнение с
исходным состоянием, а не требование нулевого общего числа marker.

`docs/research/2026-08-31-real-query-semantic-benchmark.md`. Старые проценты и

## Известные ограничения

- Интеграционные UI-тесты подтверждают пользовательский каталог и основные
  параметры, но не заменяют проверку каждого варианта прикладных данных.
- Два headless YAxUnit-теста формы остаются пропущенными из-за различия
  `ДеревоЗначений` и данных формы.
- Runtime MCP был подключён к другой ИБ и не использован как feature
  acceptance; подробности вынесены в отдельный runtime-отчёт.
