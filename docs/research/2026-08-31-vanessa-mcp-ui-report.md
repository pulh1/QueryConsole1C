# Vanessa MCP: проверка UI каталога поставщиков метаданных

Дата проверки: 2026-09-01.

## Итог

Vanessa MCP оказался полезен именно как UI acceptance-контур. Через него
полностью выполнены три новых сценария каталога поставщиков и два существующих
регрессионных сценария. Он подтвердил то, чего не может доказать серверный
YAxUnit: фактическую иерархию `ДанныеФормыДерево`, ленивое раскрытие строк,
добавление источников и полей, отображение псевдонимов и условное появление
группы временных таблиц.

При этом MCP не был эффективным основным циклом разработки. Начальная настройка
manager base, внешней компоненты, безопасного режима, библиотек и локализации
заняла существенно больше времени, чем сами прогоны. Для контрактов BSL и
быстрой диагностики EDT-MCP/YAxUnit остались основными инструментами.

## Проверенная среда

- Vanessa Automation `1.2.043.28`;
- `client_mcp` `0.6.5`;
- платформа 1С `8.3.27`;
- Streamable HTTP MCP, согласованный протокол `2025-06-18`;
- отдельная файловая manager base;
- отдельный target test client с `/TESTCLIENT`;
- запуск сценариев без EDT debugger.

Пути к базам, имя пользователя, credentials, session identifiers и PID в
отчёт не включены.

## Что выполнено через Vanessa MCP

Использовались операции состояния, подключения test client, анализа формы,
управления переменными, загрузки feature, проверки синтаксиса и выполнения
сценариев. В прямой MCP-сессии фактически вызывались `load_features`,
`check_syntax`, `run_scenario`, `get_form_analysis`, `manage_variables` и
связанные операции состояния/подключения.

Новый feature
`features/СозданиеЗапросовВКонструкторе/КаталогПоставщиковМетаданных.feature`
дал три успешных сценария:

1. корневые группы и ветки стандартного и исполняемого поставщиков;
2. добавление стандартного и исполняемого источников, вложенного поля и
   псевдонимов;
3. отсутствие группы временных таблиц до создания ВТ и её последнее положение
   после создания.

Повторно успешно выполнены существующие регрессии:

- `ТестСотрудникиОрганизацииБезВТФизлица.feature` — наблюдаемое время
  последнего прогона 16,8 секунды;
- `ТестПараметрыСрезаПоследних.feature` — успешный прогон занял больше одного
  30-секундного окна ожидания MCP.

Проверка синтаксиса нового feature после подключения библиотек вернула
0 проблем. Итоговый серверный контроль через EDT-MCP/YAxUnit дал 66 тестов:
64 passed, 0 failed, 0 errors, 2 skipped по известному ограничению подмены
`ДанныеФормыДерево` на `ДеревоЗначений`.

## Ошибки и их источник

| Наблюдение | Источник | Вывод или обход |
| --- | --- | --- |
| `open_feature_file`, `load_features` и `check_syntax` падали на конструкторе `Файл` | Безопасный режим расширения `client_mcp` и защита опасных действий в manager base | Для доверенной изолированной manager base сняты оба ограничения, клиент перезапущен |
| После установки появилось окно «Внешняя компонента успешно установлена» | Однократная установка `WebTransport` | Требуется полный перезапуск клиента; окно не является ошибкой feature |
| Повторялись предложения включить расширение | Расширение/компонента применялись не в том жизненном цикле клиента | Проверять активную базу и расширение, подтверждать и полностью перезапускать клиент |
| `load_features` по каталогу не работал | Реализация ожидает конкретный `.feature`, хотя описание параметра допускает другое прочтение | Загружать один feature за вызов |
| Загрузка прерывалась из-за двух одинаковых экспортных сценариев | В библиотеке существовали канонический файл и файл с опечаткой с одной сигнатурой | Ошибочный дубликат удалён, переиспользуется один сценарий |
| `check_syntax` мог вернуть ложный зелёный результат | Каталог экспортных библиотек не был подключён | Сначала сохранять библиотеку в обычной форме Vanessa и проверять разрешение шагов |
| Номера строк ошибки указывали на импортированную библиотеку | Особенность диагностики Vanessa | Проверять как target feature, так и экспортный сценарий по указанной сигнатуре |
| Параметр каталогов библиотек обычного запуска игнорировался | Запуск Vanessa через текущий manager profile | Каталог сохранён через UI; self-test mode не использовать |
| `StartFeaturePlayer` отключал редактор | Выбран режим проигрывателя, не обычная форма | Открывать Vanessa без режима самотестирования |
| Скриншот-инструменты сообщали подключение, но не определяли PID test client | Ограничение текущего Vanessa provider | Во время долгих ожиданий использовался системный снимок всего экрана |
| Сценарии с `Да`/`Нет` не находили значения | Системный интерфейс платформы был английским (`Yes`/`No`) | Только во временной копии набора подставлены системные значения; репозиторные сценарии оставлены русскими |
| Onec Runtime MCP вернул `Transport closed` | Недоступность отдельного runtime frontend | Runtime не использовался как доказательство UI; контур и его репозиторий не менялись |

## Изменения сценариев, найденные благодаря MCP

MCP выявил несколько проблем не в производственном BSL, а в библиотеке
приёмочных сценариев:

- параметры экспортного сценария поля перекрывали друг друга; им даны разные
  имена;
- маски заголовка конструктора в нескольких экспортных сценариях были слишком
  строгими; сохранён существующий wildcard-контракт;
- удалён файл с опечаткой, дублировавший сигнатуру канонического экспортного
  сценария;
- assertions нового feature разведены по реальным таблицам формы:
  выражения проверяются в `ПоляЗапроса`, псевдонимы — в `Псевдонимы`.

Изменение `Нет` → `No` выполнялось только во внешней временной копии suite и не
вошло в Git.

## Чем MCP был полезен

- Дал end-to-end доказательство поведения управляемой формы и реального
  test client.
- Обнаружил ошибки экспортных сценариев и отличие фактических имён таблиц формы
  от предположений.
- Подтвердил ленивое раскрытие стандартных групп и исполняемых представлений.
- Подтвердил временные таблицы в настоящем UI, где YAxUnit вынужден пропускать
  два теста из-за различий типов дерева.
- Анализ формы помогал отделять ошибку шага Vanessa от ошибки приложения.
- Системные скриншоты во время ожиданий показали отсутствие блокирующих окон и
  отсутствие режима отладки.

## Чем MCP мешал

- Persistent state manager base делал результат зависимым от последнего режима
  Vanessa, сохранённых библиотек и старой MCP-сессии.
- Модальные окна компоненты и расширения превращали timeout в неоднозначный
  сигнал: долгий сценарий и заблокированный клиент выглядели одинаково без
  снимка экрана.
- Схема некоторых tools не полностью совпадала с фактическим контрактом.
- Ложный зелёный `check_syntax` без библиотек мог создать ошибочную уверенность.
- Локализация системного интерфейса влияла на Gherkin независимо от языка
  конфигурации.
- Настройка контура потребовала заметно больше времени, чем прогон уже готовых
  сценариев.

## Сравнение контуров

| Контур | Лучшее применение | Ограничение в этой задаче |
| --- | --- | --- |
| EDT-MCP | Источник истины для BSL, метаданных, записи с hash guard и диагностик | Не доказывает интерактивное поведение формы |
| YAxUnit | Быстрые серверные контракты, TDD и полный повторяемый regression gate | Не воспроизводит `ДанныеФормыДерево` через обычное `ДеревоЗначений` |
| Vanessa MCP | Пользовательский UI, экспортные шаги, реальный test client | Высокая стоимость bootstrap, persistent state и модальные окна |
| Onec Runtime MCP | Точечные runtime-пробы при доступном frontend | В этой сессии transport был закрыт; для UI не использован |

## Рекомендация

Использовать Vanessa MCP после стабилизации серверных контрактов, как короткий
acceptance-gate для нескольких наиболее ценных UI-сценариев. Основной цикл
оставлять за EDT-MCP/YAxUnit. Для CI или контейнера заранее автоматизировать
создание manager base, установку `client_mcp`/`WebTransport`, настройку
библиотек и обработку первого запуска; без этого headless-контур остаётся
зависимым от ручных подтверждений.

Переносимая последовательность настройки и troubleshooting вынесены в
`documentation/VanessaMCP.md`.
