# Vanessa Automation через MCP

Эта инструкция описывает воспроизводимый контур, в котором отдельная база
1С управляет Vanessa Automation и публикует её инструменты через Streamable
HTTP MCP. Целевая тестовая база, база-менеджер Vanessa и EDT — разные
процессы. Не подключайте MCP-расширение к рабочей базе.

Проверенная связка на момент подготовки инструкции:

- Vanessa Automation `1.2.043.28`;
- `client_mcp` `0.6.5`;
- платформа 1С `8.3.27`.

Для другого проекта версии можно заменить согласованным комплектом. Важно
сначала добиться стабильного запуска менеджера, и только затем подключать
целевой test client.

## Что потребуется

1. Однофайловая обработка `VanessaAutomation*.epf` из официального релиза
   Vanessa Automation.
2. Расширение `client_mcp.cfe` и поставляемая с ним внешняя компонента
   `WebTransport`.
3. Расширение `VAExtension` из того же комплекта Vanessa Automation, если
   сценарии используют его возможности.
4. Отдельная пустая файловая база — менеджер Vanessa.
5. Отдельная целевая тестовая база и отдельный профиль test client.

Не храните пароли и пути к пользовательским базам в репозитории. Локальные
параметры запуска держите вне Git.

## Однократная настройка базы-менеджера

1. Создайте пустую файловую базу на совместимой версии платформы.
2. Установите `client_mcp.cfe` в базу-менеджер и обновите конфигурацию базы.
3. Для расширения `client_mcp` отключите безопасный режим и защиту от опасных
   действий. Иначе вызовы Vanessa, создающие `Файл`, могут завершаться ошибкой
   `Ошибка при вызове конструктора (Файл)`.
4. Запустите базу-менеджер в режиме 1С:Предприятия и откройте управление MCP.
5. При первом запуске согласитесь на установку внешней компоненты
   `WebTransport`. После сообщения «Внешняя компонента успешно установлена»
   полностью закройте клиент 1С и запустите его заново.
6. Если платформа предлагает разрешить расширение или небезопасные действия,
   подтвердите это. После изменения этих разрешений также перезапустите
   клиент.
7. Откройте Vanessa Automation **без режима самотестирования**. Режим
   самотестирования использует другое состояние формы и может не видеть
   сохранённые каталоги библиотек.
8. Даже если запуск выполнен с `UseEditor=True`, нажмите в основной форме
   Vanessa кнопку **«Перейти в Vanessa Editor»**. В проверенной версии ключ
   инициализировал редактор, но не сохранял флаг его активного использования.
9. В левой панели базы-менеджера откройте раздел **MCP** и форму
   **«Управление MCP»**. Открытый TCP-порт ещё не доказывает, что форма
   управления и реестр инструментов полностью инициализированы.
10. В форме управления MCP задайте свободный локальный порт, например `9874`,
   и запустите сервер. Конечный адрес имеет вид
   `http://127.0.0.1:<порт>/mcp`.

Проверенный пример запуска менеджера:

```powershell
& 'C:\Program Files\1cv8\8.3.27.2170\bin\1cv8c.exe' ENTERPRISE `
  /TESTMANAGER `
  /IBConnectionString 'File="C:\path\to\vanessa-mcp-manager";' `
  /Execute 'C:\path\to\vanessa-automation-single.epf' `
  /C 'runMcp;mcpPort=9874;UseEditor=True;DisableFirstRunHelper'
```

Повторное появление именно окон менеджера Vanessa обычно означает, что запущен
другой профиль базы, изменения расширения не применились либо клиент не был
полностью перезапущен после установки компоненты. Проверьте имя базы,
активность расширения, снятые флаги безопасности и отсутствие второго процесса
менеджера. Диалог «Изменения конфигурации информационной базы» относится к EDT,
а не к Vanessa; его обработка описана ниже отдельно.

## Настройка целевой базы

1. Создайте отдельный профиль запуска целевой базы с ключом `/TESTCLIENT`.
2. Для русских сценариев задайте оба ключа: `/Lru` для языка системного UI и `/VLru`
   для региональных форматов. Пример: `/Lru /VLru /DisableStartupDialogs /DisableStartupMessages`.
3. Не добавляйте ключи отладки и не запускайте тот же клиент из EDT в режиме
   Debug.
4. Установите совместимое `VAExtension`, если оно требуется шагам сценариев.
   После реального обновления расширения завершите старый test client и
   запустите новый: живой клиент не подхватывает изменённое расширение.
5. В Vanessa сохраните профиль подключения test client и каталоги экспортных
   библиотек. Каталоги библиотек задавайте в самой форме Vanessa: переменная
   окружения или параметр обычного запуска может не примениться при запуске
   через MCP.

В manager base не должны выполняться бизнес-сценарии. Она только держит
Vanessa, MCP и подключение к test client.

## Подключение MCP-клиента

Codex добавляет Streamable HTTP server так:

```powershell
codex mcp add vanessa --url http://127.0.0.1:9874/mcp
```

После изменения списка MCP-серверов перезапустите сессию клиента, если новые
инструменты не появились. Сервер должен быть уже запущен в базе-менеджере.

Клиент, выполняющий JSON-RPC напрямую, должен:

1. отправить `initialize` с поддерживаемой версией протокола;
2. принимать `application/json` и `text/event-stream`;
3. сохранить заголовок `Mcp-Session-Id` из ответа;
4. отправить JSON-RPC notification `notifications/initialized`; нормальный
   HTTP-ответ на него в проверенной сборке — `202 Accepted`;
5. передавать `Mcp-Session-Id` и `MCP-Protocol-Version: 2025-06-18` во всех
   следующих запросах;
6. только после этого вызывать `tools/list` и рабочие инструменты;
7. после повторного запуска MCP-сервера выполнить новый `initialize`, а не
   переиспользовать старую сессию.

Проверенная сборка согласовывала протокол `2025-06-18`.

## Рабочий цикл

Рекомендуемый порядок одного прогона:

1. Получить состояние Vanessa и убедиться, что открыта обычная форма, а не
   self-test player.
2. Подключить или запустить целевой test client.
3. Проверить анализ формы test client до загрузки сценариев.
4. Сохранить каталоги библиотек в Vanessa.
5. Загрузить один конкретный `.feature` и выполнить проверку синтаксиса.
6. В `run_scenario` передать именно `filePath`, а не `featurePath`, и сверить имя сценария
   в ответе с запущенным файлом. Неизвестный аргумент может быть проигнорирован.
7. Запустить выбранный сценарий и ждать его завершения ограниченными
   интервалами.
8. При долгой паузе снять экран и проверить модальные окна менеджера и test
   client. Не считать отсутствие ответа признаком долгого теста автоматически.
9. Получить результаты сценария и анализ текущей формы.
10. Закрывать test client только когда следующему запуску нужна чистая сессия
   или в базе действительно обновлено расширение.

Результат, возвращённый непосредственно `run_scenario`, считайте первичным.
В проверенной версии последующий `get_VanessaAutomation_state` иногда сообщал,
что тот же файл ещё не запускался, хотя `run_scenario` уже завершился успешно.

Для диагностики полезна последовательность инструментов уровня Vanessa:
`get_VanessaAutomation_state` → `connect_test_client` →
`get_form_analysis` → `load_features` → `check_syntax` → `run_scenario` →
`get_test_results`. Точные имена и аргументы берите из `tools/list` текущей
версии сервера.

## Модальные окна

На первом запуске человеку обычно требуется выполнить три действия:

1. подтвердить установку внешней компоненты;
2. закрыть и повторно запустить клиент после успешной установки;
3. подтвердить включение расширения и разрешение небезопасных действий.

Окно подтверждения закрытия test client также блокирует автоматизацию. Перед
принудительным завершением сначала проверьте экран. Если окно появилось,
нажмите подтверждение один раз и дождитесь завершения процесса.

Диалог **«Изменения конфигурации информационной базы»** создаёт EDT при
обновлении тестовой ИБ. Он не относится к Vanessa MCP и устраняется в контуре
EDT: завершите конфликтующий клиент целевой базы, примените обновление и затем
перезапустите test client. Не пытайтесь лечить такой диалог переустановкой
`client_mcp` в базе-менеджере.

Если не задан `/Lru`, системные значения и кнопки могут называться `Yes`, `No`, `Find`,
`Close`, даже если конфигурация и Gherkin русские. Сначала зафиксируйте язык и форматы
профиля ключами `/Lru /VLru`. Не подменяйте переносимые сценарии локализованными
значениями в Git.

## Диагностика

| Симптом | Что проверить | Действие |
| --- | --- | --- |
| `Session not found` | MCP-сервер или менеджер перезапущен | Повторить `initialize` и использовать новый `Mcp-Session-Id` |
| После `initialize` пустой ответ или сессия сразу пропала | Не отправлен `notifications/initialized` | Отправить notification, дождаться `202 Accepted`, затем вызвать `tools/list` с session и protocol headers |
| `Ошибка при вызове конструктора (Файл)` | Безопасный режим `client_mcp` и защита опасных действий | Отключить оба ограничения для доверенной базы-менеджера и перезапустить клиент |
| `load_features` не принимает каталог | Фактический контракт текущей версии расходится с tool schema, где каталог разрешён | Передавать путь к одному `.feature` |
| `run_scenario` выполнил не тот файл | Передан `featurePath` вместо схемного `filePath` | Сверить `tools/list`, повторить с `filePath` и проверить имя сценария в ответе |
| `check_syntax` неожиданно зелёный | Подключены ли экспортные библиотеки | Сначала сохранить каталог библиотек, повторно загрузить feature и проверить число найденных шагов |
| Ошибка указывает строку библиотечного feature | Импортирован ли одноимённый сценарий | Открыть указанную экспортную фичу; номер строки относится не обязательно к целевому файлу |
| Загрузка обрывается на дублирующемся шаге | Два экспортных сценария имеют одинаковую сигнатуру | Оставить один канонический файл, удалить или переименовать ошибочный дубликат |
| `lineNumber` отсутствует или равен нулю | Редактор Vanessa пуст либо feature ещё не открыт | Сначала загрузить/открыть конкретный feature |
| Инструменты Vanessa не видны в MCP-клиенте | Клиент не перечитал конфигурацию серверов | Перезапустить MCP-клиент после `codex mcp add` |
| Test client не отвечает | Модальное окно, отладчик EDT или stale client | Снять экран, отключить debugger, закрыть только конфликтующий клиент и запустить профиль `/TESTCLIENT` заново |
| Каталоги библиотек пропали | Vanessa открыта в self-test mode или другом профиле | Открыть обычную форму и сохранить каталоги вручную |
| Скриншот-инструмент не находит PID | Профиль Vanessa сохранил PID test client как `0` либо не сопоставил процесс | Сценарии могут продолжать работать; использовать системный снимок экрана и отдельно зафиксировать активные окна |
| `get_VanessaAutomation_state` после успешного прогона показывает «не запускался» | Состояние формы не синхронизировалось с завершённым вызовом | Использовать прямой результат `run_scenario` и отчёт прогона как доказательство |

## Изоляция процессов

- Не запускайте Vanessa, YAxUnit и EDT-debugger одновременно против одной
  файловой базы.
- Перед обновлением расширения завершите только клиентов этой базы; не убивайте
  все процессы 1С без проверки командной строки.
- Менеджер Vanessa можно держать постоянно. Перезапуск MCP frontend не требует
  закрывать target test client, если сессия и расширения не изменились.
- При долгом ожидании сначала снимите экран и проверьте модальные окна, затем
  журналы и только после этого перезапускайте процесс.

## Что считать доказательством

MCP подтверждает пользовательское поведение формы, последовательность окон и
реальную исполнимость Gherkin. Он не заменяет:

- EDT-диагностики модулей и метаданных;
- YAxUnit для быстрых серверных контрактов;
- обновление тестовой базы после изменения расширения;
- отдельную проверку производительности без отладчика.

Для воспроизводимого результата в отчёте сохраняйте версию Vanessa,
`client_mcp`, платформы, имена сценариев, фактический результат и все ручные
подтверждения. Не сохраняйте credentials, токены, PID и бизнес-данные.
