# Разработка запросов QueryConsoleZUP

Работай только с названным текстом прикладного запроса. Если изменяются lexer, parser, AST, model или generator без изменения конкретного текста запроса, не запускай этот workflow: используй `queryconsole-bsl-development`. При реальном пересечении skills предпочитай наиболее узкий.

## Workflow

1. Установи точный файл, фрагмент запроса, связанные параметры, входные данные, ожидаемый результат и границы изменения.
2. Получи реальные имена и типы метаданных из живого проекта. Не выдумывай объекты, поля или их типы.
3. До правки зафиксируй смысл: параметры, диалект, форму результата, семантику `NULL`, дубликатов и прикладное значение результата.
4. Вноси минимальную правку. Применяй приёмы производительности только при наличии доказательств и явного объяснения, почему семантика сохранится; не переписывай запросы безусловно.
5. Обнаружь доступные сейчас возможности EDT-MCP по живому руководству инструмента и проверь конкретный запрос ими. В плановом ответе не перечисляй имена вызовов, аргументы или полный каталог API; до живого discovery говори только о нужной проверке. Если проверка недоступна, укажи это.
6. Синхронизируй входы и ожидаемые артефакты лишь в запрошенных границах.
7. Сообщи выполненные проверки, семантические риски и недоступные валидации.

## Quick reference

| Нужно | Сначала установить |
| --- | --- |
| Изменить условие | Параметры, типы и `NULL`-семантику |
| Убрать дубликаты | Требуемую кратность и форму результата |
| Ускорить запрос | Наблюдаемую причину и сохранение смысла |
| Обновить пример | Связанные входы и ожидаемый артефакт в scope |

## Common mistakes

- Подменять реальные метаданные правдоподобными названиями.
- Терять параметры, диалект, порядок полей, `NULL` или дубликаты.
- Объявлять оптимизацию безопасной без доказательств и проверки смысла.
- Переписывать несвязанные примеры или эталоны.
- Применять workflow прикладного запроса к parser-only изменению.
