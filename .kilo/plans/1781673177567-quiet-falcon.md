# План исправления ошибки конструктора запроса

## Проблема

При открытии расширенного конструктора запроса из формы консоли возникает ошибка `Индекс находится за границами массива`.

Стек указывает на `DataProcessors/КонструкторЗапросов/Forms/КонструкторЗапросов/Module.bsl`, метод `ЗапросВДанные()`, строку с обращением:

```bsl
МодельЗапроса.Элементы[ИндексЗапроса]
```

## Найденная причина

Параметры обычного редактора запроса создаются в `CommonModules/КонструкторЗапросовКлиентСерверФормы/Module.bsl` с `ИндексЗапросаПакета = -1`.

При открытии из `DataProcessors/КонсольЗапросов/Forms/Форма/Module.bsl` параметр не переопределяется:

```bsl
ПараметрыОткрытия = КонструкторЗапросовКлиентСерверФормы.ПараметрыРедактораЗапроса();
ПараметрыОткрытия.ИсходныйТекстЗапроса = ТекстЗапросаВФорме;
```

В `ПриСозданииНаСервере()` формы конструктора значение `-1` попадает в `ИндексЗапроса`, затем `ЗапросВДанные()` обращается к `МодельЗапроса.Элементы[-1]`, если это не вложенный запрос.

## План изменений

1. В `DataProcessors/КонструкторЗапросов/Forms/КонструкторЗапросов/Module.bsl` добавить серверную служебную процедуру нормализации текущего индекса запроса пакета.

Предлагаемая логика:

```bsl
&НаСервере
Процедура НормализоватьИндексЗапроса(МодельЗапроса)

    Если ЭтоВложенныйЗапрос Тогда
        Возврат;
    КонецЕсли;

    Если МодельЗапроса.Элементы.Количество() = 0 Тогда
        Возврат;
    КонецЕсли;

    Если ИндексЗапроса < 0 Или ИндексЗапроса > МодельЗапроса.Элементы.ВГраница() Тогда
        ИндексЗапроса = 0;
    КонецЕсли;

КонецПроцедуры
```

2. В `ПриСозданииНаСервере()` вызвать нормализацию после получения/разбора/создания `МодельЗапроса` и до `КонструкторЗапросовФормы.МодельЗапросаВоВременноеХранилище()` или минимум до первого `ЗапросВДанные(МодельЗапроса)`.

Предпочтительно до создания реестра поставщиков метаданных, если текущий индекс нужен реестру. Сейчас реестр создаётся до разбора текста запроса, поэтому в минимальном исправлении безопаснее:

- оставить создание реестра как есть, чтобы не менять последовательность инициализации;
- нормализовать индекс сразу после формирования `МодельЗапроса` и перед `ЗапросВДанные()`;
- при необходимости после правки проверить, не требуется ли пересоздание/сброс реестра для индекса `0`.

3. Усилить `ЗапросВДанные(МодельЗапроса)` локальной защитой, чтобы метод не падал при пустом пакете или некорректном индексе из других вызовов.

Вариант минимального исправления:

```bsl
Процедура ЗапросВДанные(МодельЗапроса)
    НормализоватьИндексЗапроса(МодельЗапроса);

    Если Не ЭтоВложенныйЗапрос И МодельЗапроса.Элементы.Количество() = 0 Тогда
        Возврат;
    КонецЕсли;

    Если ЭтоВложенныйЗапрос 
        Или МодельЗапроса.Элементы[ИндексЗапроса].Тип = "ЗапросВыбора" Тогда
```

4. Проверить смежный дефект в `УдалитьЗапрос()`:

```bsl
Если МодельЗапроса.Элементы.Количество() = 0 Тогда
    ПостроительМоделиЗапроса().ДобавитьЗапросВыбора();
    ИндексЗапроса = 0;
    ЗапросВДанные(МодельЗапроса);
```

Здесь создаётся новый построитель, но результат не сохраняется в `МодельЗапроса`. Если этот сценарий воспроизводится, исправить так, чтобы после добавления запроса выбора модель заново сохранялась через `ЗавершитьРедактированиеМодели(Построитель)`.

5. Не менять `ПараметрыРедактораЗапроса()` на `0` без дополнительной проверки, потому что `-1` может быть осознанным маркером отсутствия выбранного запроса для других сценариев. Исправление лучше локализовать в форме конструктора.

## Проверки после реализации

1. Запустить диагностику EDT по проекту `QueryConsoleZUP` через доступный CodePilot/EDT-инструмент.
2. Проверить открытие расширенного конструктора из `КонсольЗапросов` для непустого текста запроса.
3. Проверить открытие конструктора для пустого текста/нового запроса.
4. Проверить переключение запросов в пакете и добавление/удаление запроса, особенно удаление последнего запроса.
5. Если есть возможность, прогнать имеющиеся тесты проекта или smoke-сценарий открытия формы.

## Ожидаемый результат

Конструктор запроса открывается при `ИндексЗапросаПакета = -1`, автоматически выбирая первый запрос пакета после разбора текста, и больше не обращается к элементам массива с отрицательным или выходящим за границы индексом.
