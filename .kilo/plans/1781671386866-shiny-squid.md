# План исправления ошибки открытия конструктора запросов

## Проблема

При обычном открытии формы `Обработка.КонструкторЗапросов.Форма.КонструкторЗапросов` из формы консоли запросов в параметры открытия передается `ИсходныйТекстЗапроса`, но не передается корректный `АдресСпискаДоступныхВТ`.

В `DataProcessors/КонструкторЗапросов/Forms/КонструкторЗапросов/Module.bsl` форма при создании сразу вызывает:

```bsl
ОписаниеДоступныхВТ = ПолучитьИзВременногоХранилища(АдресСпискаДоступныхВТ);
```

Если `АдресСпискаДоступныхВТ` пустой, платформа выбрасывает ошибку `Недопустимое значение параметра` для `ПолучитьИзВременногоХранилища()`.

## Найденные места

- `QueryConsoleZUP/src/DataProcessors/КонсольЗапросов/Forms/Форма/Module.bsl:2317-2326` открывает обычный конструктор через `ПараметрыРедактораЗапроса()` и не заполняет адрес списка ВТ.
- `QueryConsoleZUP/src/CommonModules/КонструкторЗапросовКлиентСерверФормы/Module.bsl:86-92` формирует параметры обычного редактора без `АдресСпискаДоступныхВТ` и `ИндексЗапросаПакета`.
- `QueryConsoleZUP/src/DataProcessors/КонструкторЗапросов/Forms/КонструкторЗапросов/Module.bsl:20-28` при создании формы создает реестр поставщиков через `ОписаниеДоступныхВТИзВременногоХранилища()`.
- `QueryConsoleZUP/src/DataProcessors/КонструкторЗапросов/Forms/КонструкторЗапросов/Module.bsl:1526-1533` функция читает временное хранилище без проверки заполненности адреса.
- Для вложенных запросов адрес заполняется отдельно в `ПараметрыОткрытияВложенногоЗапроса()`, поэтому там сценарий защищен.

## План изменений

1. В `CommonModules/КонструкторЗапросовКлиентСерверФормы/Module.bsl` дополнить `ПараметрыРедактораЗапроса()` теми же базовыми полями, которые ожидает форма конструктора:

```bsl
ПараметрыРедактора.Вставить("ИндексЗапросаПакета", -1);
ПараметрыРедактора.Вставить("АдресСпискаДоступныхВТ", "");
```

2. В `DataProcessors/КонструкторЗапросов/Forms/КонструкторЗапросов/Module.bsl` сделать `ОписаниеДоступныхВТИзВременногоХранилища()` устойчивой к пустому адресу:

```bsl
Если Не ЗначениеЗаполнено(АдресСпискаДоступныхВТ) Тогда
	ОписаниеДоступныхВТ = Новый Массив;
Иначе
	ОписаниеДоступныхВТ = ПолучитьИзВременногоХранилища(АдресСпискаДоступныхВТ);
КонецЕсли;
```

Существующий блок повторного помещения во временное хранилище оставить без изменения, чтобы после первого вызова пустой список тоже получил валидный адрес, привязанный к `УникальныйИдентификатор` формы.

3. Рассмотреть аналогичную защиту в общем helper-методе `КонструкторЗапросовФормы.ОписаниеДоступныхВТИзВременногоХранилища(Форма, ДляИзменения = Ложь)`, если при реализации будет видно, что этот helper может вызываться для форм с пустым `АдресСпискаДоступныхВТ`. Минимально обязательное исправление для текущего стека находится в форме конструктора.

4. Не менять логику вложенных запросов: там список доступных ВТ должен передаваться из родительского конструктора и уже заполняется через временное хранилище.

## Проверки после реализации

1. Запустить диагностику EDT/CodePilot по проекту `QueryConsoleZUP` или минимум по измененным BSL-модулям.
2. Проверить открытие расширенного конструктора из `Обработка.КонсольЗапросов.Форма.Форма` для обычного текста запроса без временных таблиц.
3. Проверить открытие вложенного конструктора из формы конструктора, чтобы передача доступных ВТ не регрессировала.
4. Если доступен runtime-сценарий, проверить открытие конструктора из `Отчет.УниверсальныйОтчетРасширенный.Форма.РедакторЗапроса`, так как он использует тот же `ПараметрыРедактораЗапроса()`.

## Ожидаемый результат

Обычный конструктор запросов открывается без ошибки `ПолучитьИзВременногоХранилища`, а при отсутствии доступных временных таблиц использует пустой массив описаний ВТ.
